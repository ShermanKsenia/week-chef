# Спецификация: Observability / Evals

## Метрики (минимум)
- **Latency:** время полного «план на неделю», время шага `validate_plan`, время `get_recipes`, **длительность каждого вызова LLM** (по имени шага/промпта).
- **Счётчики:** число вызовов LLM, tool calls по имени; число `validate_plan` fail и коды `reason_codes`.
- **Надёжность внешних API:** ошибки по типу (`TIMEOUT`, `429`, `5xx`) на каждый tool и отдельно по LLM
- **Очередь / async:** при фоновом построении плана — **глубина очереди**, время ожидания в очереди, число зависших задач (stale).
- **Стоимость:** токены в/из LLM на запрос.
- **Качество LLM (техническое):** доля успешного парсинга JSON по схеме; число ретраев из-за невалидного JSON; число переключений на fallback-модель; число ответов с кодом `LLM_UNAVAILABLE`.
- **Качество агента (продуктовое):** классификация фидбека по завершении недели, доля выполненных дней плана; офлайн-оценки (DeepEval / RAGAS) на фиксированном наборе кейсов.

## Логи
- Структурированный лог: `correlation_id`, `user_id`, `step`, `tool`, `duration_ms`, `result=ok|error`, `error_code`.
- Для вызовов LLM: дополнительно `model`, `prompt_version` (без текста промпта целиком).
- **Запрещено:** сырой пользовательский ввод целиком, названия событий календаря, free-text аллергий — см. `governance.md`.
- Допустимо: короткий **хэш** запроса, коды отказов валидатора.

## SLO и «красная зона»
- Фиксированные пороги в конфиге или документе релиза: например доля ошибок LLM **> X%** за час, p95 latency полного плана **> Y s** — **сигнал к расследованию** (даже если алерт только ручной просмотр дашборда раз в день).
- **Error budget:** при превышении доли `LLM_UNAVAILABLE` — проверить квоты, ключи, статус провайдера.

## Трейсы
- Один trace на «один пользовательский запуск плана»: спаны `INTAKE`, `ENRICH`, `PLAN`, `VALIDATE`, `SHOPPING`; внутри `PLAN` — отдельные спаны на **каждый** вызов LLM.

## Проверки / evals
- Синтетический профиль + фикстура календаря → план проходит `validate_plan`.
- **Регрессия промптов:** несколько золотых диалогов (JSON in/out) на `parse_input`.
- **Ручная выборка:** раз в спринт проверка N планов на нарушение строгих аллергенов (0 допуска).
