# Спецификация: Memory / Context

## Session state
- Хранится привязка к пользователю: текущий черновик `weekly_plan`, последний список покупок, счётчик уточняющих вопросов, флаги «ждём ответа».
- TTL сессии: **24–72ч** без активности или до явного сброса.

## Долговременная память (профиль)
- Предпочтения, ограничения, история фидбека хранятся в БД (SQLite/Postgres).
- Обновление после `analyze_feedback`.

## Memory policy
В промпт LLM подмешивать: суммаризация запросов пользователя + текущая цель по питанию + проанализированный календарь

## Context budget (ориентиры PoC)
- Общий бюджет контекста на один вызов LLM: **~8–16k токенов** (зависит от выбранной модели).
- Резerved под системный промпт и схему tools: **~1–2k**.
- На кандидатов рецептов: **топ-K карточек** (например K≤10)
- При переполнении: сначала урезается история чата (старые реплики), затем число рецептов в контексте. 

## Обновление памяти
После получения фидбека от пользователя (в конце недели) сохранённые данные о пользователе сравниваются с новыми. Если есть противоречащая информация, приоритет отдается новой информации. Если факты дополняют информацию из памяти, то информация дозаписывается.

## Что хранить явно в state (минимум)
- цель по питанию 
- ограничения
- количество порций
- предпочтения пользователя
- прошлый план
- список покупок продуктов
