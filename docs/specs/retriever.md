# Спецификация: Retriever (рецепты / продукты)

## Назначение
Выдача кандидатов рецептов и справочных данных по продуктам для планировщика и инструмента по составлению плана питания.

## Источники (PoC)
- **Рецепты:** DB на основе таблицы с [kaggle](https://www.kaggle.com/datasets/vlad15lav/recipes-corpus-textual-data-for-nlprecsys)
В нем есть:
* прием пищи (завтрак/обед)
* ингредиенты
* время приготовления
* текст рецепта
* КБЖУ

## Индекс и хранение
- Фильтрация по времени приготовления, приему пищи, ингредиентам

## Кэш (стабильность и ресурсы, PoC)
- Кэшировать результаты поиска по ключу `(filters hash)` на **24 ч** (in-memory или Redis) — снижает нагрузку на БД и стабилизирует латентность при повторных запросах планировщика.
- При ошибке БД — см. отказоустойчивость в `governance.md` (ограниченный режим / сообщение пользователю).

## Поиск
- Вход: `filters` — `max_ready_time`, список запретов/аллергенов, прием пищи, лимит `limit` (например 20–50).
- Выход: список `{ recipe_id, title, ready_minutes, ingredients[], tags[], source_ref }`.

## Ограничения
- Лимит на количество рецептов в ретриве в соответствии с контекстом
- При падении таблицы - предупреждение пользователя о произошедшем
