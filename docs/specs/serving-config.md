# Спецификация: Serving / Config

## Запуск
- Один сервис **API + worker оркестратора**
- **Liveness:** `GET /health` → процесс жив, отвечает `ok` (без проверки внешних API).
- **Readiness:** `GET /ready` → `ok` только если доступны критичные зависимости: БД сессий/state, при необходимости — проверка DNS/достижимости endpoint LLM **без** отправки полного запроса

## Конфигурация (env / файл)
- `LOG_LEVEL`, `SESSION_TTL_HOURS`
- Лимиты: `LLM_MAX_RETRIES`, `VALIDATE_MAX_RETRIES`, `RECIPE_PAGE_LIMIT`, `CONTEXT_TOKEN_BUDGET`
- **Параллелизм и время:** `LLM_MAX_CONCURRENT` (одновременные вызовы к API LLM на инстанс), `PIPELINE_MAX_SECONDS` (верхняя граница времени на полный сценарий «план на неделю» в синхронном режиме; при превышении — отмена шага + код ошибки / переход в async).
- OAuth Google: client id/secret через env; redirect URI для PoC

## Секреты
- API keys LLM, ключи внешних рецептов, OAuth — только в env или секрет-хранилище

## Версии моделей
- Зафиксировать в конфиге: `LLM_MODEL` + **`LLM_FALLBACK_MODEL`**.
- **Когда переключаться на fallback:** после исчерпания ретраев на основной модели при ошибках транспорта (`TIMEOUT`, `5xx`, недоступность), при **429** после backoff — по политике (сначала пауза, потом fallback)
- **Если недоступны обе модели / квота исчерпана:** не зацикливать вызовы; вернуть пользователю явный код **`LLM_UNAVAILABLE`**; сохранить черновик сессии (см. `orchestrator.md`); опционально поставить задачу на **отложенный retry** (очередь in-memory/Redis на PoC).

## Политика при полном отказе LLM (PoC)
- Сообщение пользователю: сервис временно не может построить план с помощью ИИ; повторить позже / кнопка «повторить».
- **Circuit breaker (лайт):** после N подряд ошибок к одному провайдеру — пауза M секунд перед новыми вызовами (снижает лавину ретраев). Пороги N/M в конфиге.

## Минимальные SLO PoC
- Интерактивные ответы **≤10 s** p95 при отсутствии длинного планирования.
- Полный недельный прогон **≤1–2 min** или асинхронный ответ «план готовится» + webhook/polling.
- Для async: метрика **глубины очереди** / числа висящих задач (см. `observability-evals.md`).
