# Workflow / graph: выполнение запроса «план на неделю»

Пошаговый поток оркестратора: **укрупнённая** схема (мало узлов). Детальные ветки и лимиты — в `docs/system-design.md`, `docs/specs/orchestrator.md`.

## 1. Основной сценарий и ошибки

```mermaid
flowchart LR
  A([Сообщение]) --> B[Handler → Orchestrator]
  B --> C[INTAKE<br/>parse_input, уточнения<br/>до заполнения state]
  C --> D[ENRICH<br/>Calendar, Inventory]
  D --> E[PLAN<br/>неделя + по дням<br/>рецепты ↔ LLM]
  E --> F[AGGREGATE черновик]
  F --> G[VALIDATE]
  G -->|план ок| H[SHOPPING]
  G -->|ещё можно исправить| E
  G -.->|исчерпаны попытки| X
  H --> I[REPLY<br/>план + список]
  I --> OK([Успех])

  C -.->|лимиты / LLM_UNAVAILABLE| X
  D -.->|критичный сбой загрузки| X
  E -.->|нет рецептов, таймаут, LLM| X
  H -.->|редко| X
  X[Сообщение пользователю<br/>код, «Повторить» при необходимости]
  X --> FAIL([Ошибка])
```

**Что скрыто внутри блоков:**

| Блок | Внутри по сути |
|------|------------------|
| **INTAKE** | Ретраи JSON, до ~5 раундов вопросов, полный отказ LLM → `LLM_UNAVAILABLE`. |
| **ENRICH** | Деградация без полного фона или стоп при критичной ошибке. |
| **PLAN** | `get_recipes`, лимиты вызовов, `PIPELINE_MAX_SECONDS`, ослабление фильтров. |
| **VALIDATE** | До нескольких циклов «перепланировать дни»; исчерпание → объяснение пользователю. |


## 2. Упрощённый поток «перепланирование» (REPLAN)

Вход — новое сообщение после сбоя (нет продукта, сорвалась готовка, смена календаря и т.д.).

```mermaid
flowchart TD
  RSTART([Сообщение: тип сбоя + дни]) --> H2[Handler]
  H2 --> OR2[Orchestrator REPLAN]
  OR2 --> LOAD[Загрузка state, Calendar, Inventory]
  LOAD --> SCOPE[Область: затронутые дни]
  SCOPE --> PD2[PLAN_DAYS / замена рецептов]
  PD2 --> VAL2[VALIDATE фрагмента]
  VAL2 --> V2{valid?}
  V2 -->|нет| R2{retry < лимита?}
  R2 -->|да| PD2
  R2 -->|нет| FAIL2[Сообщить причину]
  V2 -->|да| SH2[SHOPPING дельта или полный пересчёт]
  SH2 --> REP2[REPLY: предложение изменений]
  REP2 --> OK2([Успех])
  FAIL2 --> E2([Ошибка])
```
